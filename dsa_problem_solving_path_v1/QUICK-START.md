## 🎯 Pattern Quick Reference

### When to Use Each Pattern

**Hash Map**
- ✅ Need O(1) lookup
- ✅ Complement search (Two Sum)
- ✅ Frequency counting
- ❌ Need sorted order

**Two Pointers**
- ✅ Array is sorted
- ✅ Find pairs/triplets
- ✅ Palindrome checking
- ✅ In-place modification

**Sliding Window**
- ✅ Contiguous subarray/substring
- ✅ "Longest/shortest" with condition
- ✅ Fixed or variable window size
- ❌ Non-contiguous elements

**Fast/Slow Pointer**
- ✅ Linked list cycle detection
- ✅ Find middle of linked list
- ✅ Detect cycle start point
- ❌ Not for arrays

**Binary Search**
- ✅ Array is sorted
- ✅ Search space can be halved
- ✅ "Find minimum/maximum X such that..."
- ✅ Rotated sorted array

**DFS (Recursion)**
- ✅ Explore all paths
- ✅ Tree/graph traversal
- ✅ Backtracking problems
- ✅ Connected components

**BFS (Queue)**
- ✅ Shortest path (unweighted)
- ✅ Level-order traversal
- ✅ Multi-source problems
- ❌ Not for finding all paths

**Dynamic Programming**
- ✅ Overlapping subproblems
- ✅ Optimal substructure
- ✅ "Maximum/minimum" optimization
- ✅ Counting ways

**Greedy**
- ✅ Local optimal → global optimal
- ✅ Interval scheduling
- ✅ Kadane's algorithm (max subarray)
- ❌ Need proof of correctness

**Backtracking**
- ✅ Generate all combinations/permutations
- ✅ Constraint satisfaction
- ✅ Pruning search space
- ❌ Not for optimization (use DP)

## 💡 Problem-Solving Checklist

### Before Coding
- [ ] Read problem 2-3 times
- [ ] Note constraints (array size, value ranges)
- [ ] List 3-4 test cases (normal, edge, large)
- [ ] Identify pattern family
- [ ] Explain brute force approach (even if inefficient)
- [ ] Plan optimal approach
- [ ] Estimate time/space complexity
- [ ] Get interviewer approval (if interview)

### While Coding
- [ ] Use meaningful variable names
- [ ] Handle edge cases first (empty, single element)
- [ ] Write helper functions if complex
- [ ] Add comments for complex logic
- [ ] Think aloud (explain your reasoning)
- [ ] Test as you code (dry run)

### After Coding
- [ ] Test with provided examples
- [ ] Test edge cases
- [ ] Walk through code line-by-line
- [ ] Analyze actual time/space complexity
- [ ] Discuss trade-offs
- [ ] Mention alternative approaches
- [ ] Ask clarifying questions for ambiguous parts

## 🚨 Common Mistakes to Avoid

### Beginner Mistakes
- ❌ Jumping to code without clear plan
- ❌ Not reading constraints carefully
- ❌ Ignoring edge cases (empty, null, single element)
- ❌ Not testing with different inputs
- ❌ Assuming arrays are sorted unless stated
- ❌ Off-by-one errors in loops
- ❌ Not handling duplicate elements

### Intermediate Mistakes
- ❌ Overcomplicating solutions
- ❌ Not considering time/space trade-offs
- ❌ Memorizing solutions instead of patterns
- ❌ Skipping brute force explanation
- ❌ Not explaining reasoning clearly
- ❌ Giving up too quickly when stuck
- ❌ Not asking for hints when needed

### Interview-Specific Mistakes
- ❌ Staying silent during problem solving
- ❌ Not clarifying ambiguous requirements
- ❌ Rushing to code without discussion
- ❌ Not testing thoroughly
- ❌ Panicking when stuck
- ❌ Arguing with interviewer
- ❌ Not managing time (45 min per problem)
